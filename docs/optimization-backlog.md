Every auditor agent cites this file. A finding should name its section (e.g. "backlog §4.2"), so the
same defect is called the same thing every time.

**Status key:** ❌ open · 🔧 in progress · ✅ done · ⏸ blocked on [business-facts.md](business-facts.md)

Baseline audited **2026-08-16** against the repo, the committed export in `out/`, **and the live site**.
Where a defect was measured, the measurement is given.

Confirmed in production on that date: the doubled `<title>` on `/about/`, the placeholder testimonials
on `/reviews/`, 43 sitemap URLs, the Cloudflare managed AI-crawler block, the security headers already
set at the edge, `www` serving a duplicate copy, and a working raw `mailto:` in the HTML.

> data-driven config and the build hygiene are all in better shape than the fleet average. What it does
> not have is depth, proof, or structured data. Read §3, §4 and §7 first — the rest is smaller.
